### [B-001] [High] [安全] tauri.dev.conf.json:6-10 — dev 配置 asset scope 含 `$HOME/**/*` 过度宽松

**描述**：dev 配置的 `assetProtocol.scope.allow` 包含 `"$HOME/**/*"`，将整个用户主目录纳入可访问范围。虽然 base 配置的 `deny` 列表（`$HOME/.ssh/**`、`$HOME/.aws/**`、`$HOME/.gnupg/**` 等）通过 Tauri 深合并保留，对敏感目录提供保护，但 `deny` 之外的整个 `$HOME`（文档、图片、桌面、下载、浏览器 profile 等）在 dev 构建中均可通过 asset 协议读取。

```json
// tauri.dev.conf.json:6-10
"allow": [
  "$APPDATA/mirrorstar/**/*",
  "$HOME/**/*",          // 整个主目录
  "wallpaper/**"
]
```

风险路径：dev 构建常被开发者打包分发给测试人员，主目录全量读取是过大的攻击面。`deny` 列表是枚举式黑名单，无法覆盖所有敏感位置（如 `$HOME/.config/**`、`$HOME/AppData/Roaming/**` 下的浏览器数据、`$HOME/Documents/**` 中的隐私文件），与 base 配置"仅允许 `$APPDATA/mirrorstar/**/*`"的最小化原则相悖。

**建议**：收窄 dev scope 至实际测试所需路径：
```json
"allow": [
  "$APPDATA/mirrorstar/**/*",
  "$APPLOCALDATA/mirrorstar/**/*",
  "$HOME/Pictures/mirrorstar-test/**/*"
]
```
若测试需读取任意壁纸路径，应通过文件对话框（`dialog:allow-open`，已授权）让用户显式选择，而非放开 `$HOME` 全量。

### [B-002] [Medium] [性能] Cargo.toml:45 — tokio `full` features 拉入未使用子模块 ✅ 已修复于 v4.0 Wave 2F

**描述**：workspace 级 `tokio = { version = "1", features = ["full"] }` 启用全部 features（含 `net`、`signal`、`process`、`io-std` 等）。本应用为 Windows 桌面壁纸工具，核心使用 `rt`、`rt-multi-thread`、`macros`、`time`、`fs`、`sync`、`io-util`，并不需要 `net`（网络监听/连接）、`signal`（Unix 信号，Windows 上几乎无用）等。`tokio` 是编译时间大户，`full` 会拉入大量未被使用的子模块及其传递依赖，显著增加 clean build 时间与二进制体积。

**建议**：按实际使用裁剪 features：
```toml
tokio = { version = "1", features = ["rt", "rt-multi-thread", "macros", "time", "fs", "sync", "io-util"] }
```
若 `mirrorstar-core` 中文件监听/异步 IO 有特殊需求，按需补充；移除 `net`/`signal`/`process`/`io-std`。

### [B-003] [Medium] [性能] Cargo.toml（无 [profile.release]）— 缺少 LTO/strip/codegen-units 优化 ✅ 已修复于 v4.0 Wave 2F

**描述**：workspace 根 Cargo.toml 未定义 `[profile.release]`，使用 cargo 默认配置（`opt-level = 3`、`lto = false`、`codegen-units = 16`、`strip = false`）。对 Tauri 桌面应用，默认配置产生的 release 二进制偏大且未剥离调试符号，且 16 个 codegen 单元阻碍了跨函数优化。release.yml 通过 `tauri-apps/tauri-action@v0` 产出的安装包内嵌未优化的二进制，影响用户下载体积与启动性能。

**建议**：在根 Cargo.toml 追加 release 优化配置：
```toml
[profile.release]
opt-level = "s"        # 或 "z" 进一步压缩体积
lto = true             # 跨 crate 链接时优化
codegen-units = 1      # 单单元，最大化优化空间
strip = "symbols"      # 剥离符号表
```
注意：`panic = "abort"` 与项目中 `catch_unwind`（见 01-config C-003、hot_reload.rs:175）冲突，若保留 panic 防护则不要设置 `panic = "abort"`。建议先引入 `lto`/`codegen-units`/`strip`，评估编译时间增量后再考虑 `panic`。

### [B-004] [Medium] [可维护性] tauri.conf.json:2 — `$schema` 指向 Tauri `dev` 分支 ✅ 已修复于 v4.0 Wave 2F

**描述**：`$schema` 指向 Tauri 仓库 `dev` 分支：
```json
"$schema": "https://raw.githubusercontent.com/tauri-apps/tauri/dev/crates/tauri-config-schema/schema.json"
```
`dev` 分支随时变动，schema 可能引入未发布字段或变更校验规则，导致：① IDE 校验结果与实际 Tauri v2 稳定版行为不一致；② 某天 `dev` 分支 schema 变更后，现有配置出现虚假的校验告警。

**建议**：固定到与 `tauri = "2"` 匹配的已发布 tag：
```json
"$schema": "https://raw.githubusercontent.com/tauri-apps/tauri/tauri-v2/crates/tauri-config-schema/schema.json"
```
或使用 `tauri-cli` 本地生成的 schema，避免依赖远端 `dev` 分支。

### [B-005] [Medium] [可维护性] tauri.conf.json:4 / Cargo.toml:10 — 版本号双处硬编码 ✅ 已修复于 v4.0 Wave 2F

**描述**：版本号在两处独立硬编码为 `"0.1.0"`：
- `Cargo.toml:10` workspace.package.version = "0.1.0"（src-tauri/Cargo.toml:3 以 `version.workspace = true` 继承）
- `tauri.conf.json:4` "version": "0.1.0"（独立硬编码）

Tauri v2 在 `tauri.conf.json` 省略 `version` 字段时会自动从 `Cargo.toml` 读取。当前双处维护，发版时极易遗漏其一，导致：安装包 `Cargo.toml` 版本与 Tauri bundle 元数据版本不一致；updater 校验版本时出现错配。

**建议**：从 `tauri.conf.json` 移除 `version` 字段，统一由 `Cargo.toml` 的 `workspace.package.version` 作为唯一来源；发版时仅修改 Cargo.toml 一处（或通过 `tauri-action` 的 `tag` 驱动）。

### [B-006] [Medium] [安全] ci.yml:58-59 — npm audit `--omit=dev` 不检查 devDependencies

**描述**：前端安全审计 `npm audit --omit=dev --audit-level=high` 仅检查生产依赖，且阈值设为 `high`。devDependencies（`vite`、`vitest`、`eslint`、`typescript-eslint`、`terser`、`jsdom` 等）的漏洞不会被检查。dev 依赖供应链风险同样不可忽视：构建工具链中存在恶意 postinstall 脚本可在 CI 构建时执行任意代码、窃取 `GITHUB_TOKEN` 或签名密钥。`--omit=dev` 使此类风险完全绕过 CI 审计。

**建议**：增加一轮 dev 依赖审计（可设为 non-fatal 或 `--audit-level=critical`）：
```yaml
- name: Security audit (production)
  run: npm audit --omit=dev --audit-level=high
- name: Security audit (dev, critical only)
  run: npm audit --audit-level=critical
```
或启用 Dependabot 对 dev 依赖的安全告警（见 B-014）。

### [B-007] [Medium] [错误处理] release.yml:59-69 — release secrets 未校验存在性 ✅ 已修复于 v4.0 Wave 2F

**描述**：`tauri-apps/tauri-action@v0` 步骤无条件注入 `TAURI_SIGNING_PRIVATE_KEY` 与 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 两个 secret。若仓库未配置这两个 secret（如 fork 构建、新成员首次发版、secret 被误删），`tauri-action` 会在**完成整个 Rust+前端编译后**才在签名阶段失败或静默跳过签名。前者浪费完整编译时间（Windows Tauri 全量构建耗时较长）；后者产出**未签名**的安装包，updater 将无法校验更新，用户静默安装不可信产物。

**建议**：
1. 在 release job 起始处显式校验 secret 存在性，fail-fast（注：GitHub Actions 不允许在 `run` 中直接引用 `secrets` 上下文做 `-z` 判断，需改用 `${{ }}` 表达式输出到 env 再判断，或用 `if: ${{ secrets.X != '' }}` 步骤条件）。
2. 在 README 或发版文档中明确列出 release 所需 secret 清单。

### [B-008] [Medium] [性能] .cargo/config.toml:1-5 — rsproxy.cn 镜像提交入库影响 CI ✅ 已修复于 v4.0 Wave 2F

**描述**：提交入库的 `.cargo/config.toml` 将 crates.io 全局替换为 `rsproxy.cn`（国内镜像）：
```toml
[source.crates-io]
replace-with = 'rsproxy-sparse'
[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"
```
该配置对**所有** cargo 操作生效，包括 GitHub Actions（ci.yml runner 位于美国）。影响：
1. **CI 可靠性**：GitHub runner → rsproxy.cn（中国境内）跨地域拉取索引与 crate 包，延迟高；rsproxy.cn 宕机或限流时 CI 直接失败（单一故障点）。
2. **贡献者体验**：非中国区贡献者克隆仓库后被迫使用国内镜像，拉取速度反而下降。
3. 提交区域特定镜像不符合 Cargo 配置最佳实践（应作为用户级 `~/.cargo/config.toml` 或环境变量配置）。

**建议**：
1. 从仓库移除 `.cargo/config.toml` 中的 source 替换，改为本地用户配置或文档说明（README 中给出 `rsproxy`/`sccache` 等加速建议）。
2. 若必须在 CI 使用镜像，在 CI 中通过环境变量按需设置，而非提交全局替换。
3. 至少在 CI 中不强制走 `rsproxy.cn`，让 GitHub runner 直连 crates.io sparse 索引。

### [B-009] [Low] [安全] tauri.dev.conf.json:9 — dev scope `"wallpaper/**"` 相对路径解析基准不明

**描述**：dev scope `allow` 中包含 `"wallpaper/**"` —— 相对路径，未使用 Tauri 路径变量（如 `$APPDATA`、`$HOME`、`$RESOURCE`）。Tauri assetProtocol scope 对相对路径的解析基准未明确文档化（通常相对当前工作目录或资源目录），该条目很可能无法按预期匹配任何实际壁纸路径，属于无效/误导性配置，可能是早期调试遗留。

**修复状态**：✅ 已自动修复于 v4.0 Wave 1B（B-001 修复时附带移除 dev scope 中的 `wallpaper/**`，当前 dev scope 仅含 `$APPDATA/mirrorstar/**/*`、`$APPLOCALDATA/mirrorstar/**/*`、`$HOME/Pictures/mirrorstar-test/**/*` 三条目，Wave 3I 仅做状态标注无代码改动）

**建议**：移除 `"wallpaper/**"`，或改为基于路径变量的绝对范围（如 `"$RESOURCE/wallpaper/**"`）并在注释中说明用途。

### [B-010] [Low] [性能] ci.yml:26-30 — cargo build + cargo test 冗余步骤

**描述**：`rust-checks` job 依次执行 `cargo build --workspace` 与 `cargo test --workspace`。`cargo test` 已隐含编译（含 test target 与 default target），前一步 `cargo build` 的产物对 `cargo test` 无增量价值，属于冗余步骤。虽因 `rust-cache` 缓存命中影响有限，但首次/依赖变更时仍多一次无用编译。

**修复状态**：✅ 已修复于 v4.0 Wave 3I（移除 `.github/workflows/ci.yml` 中 rust-checks job 的独立 `Build` 步骤，由 `Test` 步骤覆盖编译验证）

**建议**：移除独立的 `Build` 步骤，由 `Test` 步骤覆盖编译验证；或将其改为 `cargo build --workspace --release` 以额外验证 release profile 编译（当前 CI 未验证 release profile 编译，release.yml 也仅在最终 `tauri-action` 时才触发 release 构建）。

### [B-011] [Low] [可维护性] eslint.config.js:25-26 — `no-console: off` 与注释自相矛盾

**描述**：规则配置与注释自相矛盾：
```js
// 日志统一走 logger 模块，不再直接使用 console（logger.ts 内部除外）
"no-console": "off",
```
注释声明"不再直接使用 console"，但规则设为 `"off"`（完全禁用检查），即对 console 使用**零约束**。与同文件中 `@typescript-eslint/no-explicit-any` 设为 `"warn"` 的"渐进收紧"策略不一致——`no-console` 连 warn 都未保留，无法在后续代码中提示开发者改用 logger。

**修复状态**：✅ 已修复于 v4.0 Wave 3I（`eslint.config.js` 中 `no-console` 从 `"off"` 改为 `"warn"`，并新增 overrides 对 `src/scripts/utils/logger.ts` 放行）

**建议**：将 `no-console` 设为 `"warn"`（与 `no-explicit-any` 一致的渐进策略），或为 `logger.ts` 配置 overrides 放行后设为 `"error"`：
```js
"no-console": "warn",
// overrides 中对 logger.ts 放行
{ files: ["src/scripts/logger.ts"], rules: { "no-console": "off" } }
```

### [B-012] [Low] [可维护性] vitest.config.ts:13-16 — coverage 缺 `statements` 阈值

**描述**：coverage 阈值定义了 `lines`、`branches`、`functions` 三项，缺少 `statements`：
```ts
thresholds: {
  lines: 70,
  branches: 60,
  functions: 70,
  // 缺 statements
},
```
v8 coverage 的 `statements` 与 `lines` 通常接近但不等价（单行多语句、跨行语句）。缺少 `statements` 阈值意味着语句覆盖可低于 70% 而不触发 CI 失败，覆盖率门禁存在盲区。与前端审查其他模块时常见的四项全覆盖惯例不一致。

**修复状态**：✅ 已修复于 v4.0 Wave 3I（`vitest.config.ts` 的 `coverage.thresholds` 补充 `statements: 70`，与 lines 对齐保持四项阈值完整）

**建议**：补充 `statements: 70`（或与 `lines` 对齐），保持四项阈值完整。

### [B-013] [Low] [架构设计] src-tauri/Cargo.toml:8-10 — `crate-type` 含无用 cdylib/staticlib

**描述**：`[lib]` 声明 `crate-type = ["lib", "cdylib", "staticlib"]`。本应用为 Windows-only 桌面应用（依赖 `webview2-com`、WorkerW、`winreg`），桌面产物由 `src/main.rs` 自动检测为 binary。`cdylib`（动态库，用于移动端 Tauri 加载）与 `staticlib`（静态库，用于 FFI/移动端）在纯 Windows 桌面场景无用，但 `cargo build` 仍会为这两个 crate-type 生成产物，增加编译时间与 target 目录体积。

**修复状态**：✅ 已修复于 v4.0 Wave 3I（`src-tauri/Cargo.toml` 中 `[lib]` 的 `crate-type` 从 `["lib", "cdylib", "staticlib"]` 裁剪为 `["lib"]`，验证 `cargo build --workspace` 与 `cargo test --workspace` 均通过）

**建议**：桌面专用场景裁剪为 `crate-type = ["lib"]`（或仅保留实际需要的）。若未来计划支持移动端，再按需添加 `cdylib`/`staticlib`。注意：移除 `cdylib` 前确认 `tauri-build` 未要求（标准 Tauri v2 桌面模板可仅用 lib + bin）。

### [B-014] [Low] [可维护性] .github/（无 dependabot.yml）— 依赖更新完全依赖人工

**描述**：`.github/` 目录下仅有 `workflows/ci.yml` 与 `release.yml`，未配置 Dependabot 或 Renovate。依赖更新完全依赖人工手动 bump：
- Rust 侧：`windows = "0.58"`、`tauri = "2"`、`image = "0.25"` 等以主版本锁定，次版本/补丁更新不会被主动发现。
- npm 侧：`@tauri-apps/api`、`vite` 等使用 caret 范围，`npm ci` 会按 lockfile 安装，但 lockfile 不会自动升级。

结合 B-006（dev 依赖审计缺失），供应链安全与依赖新鲜度缺乏自动化机制。`cargo audit` / `npm audit` 仅在 CI 触发时被动发现已知漏洞，无法主动跟进补丁版本。

**修复状态**：✅ 已修复于 v4.0 Wave 3I（新增 `.github/dependabot.yml`，覆盖 cargo / npm / github-actions 三生态，weekly 调度，open-pull-requests-limit: 5）

**建议**：添加 `.github/dependabot.yml`，覆盖 cargo、npm 与 github-actions 生态：
```yaml
version: 2
updates:
  - package-ecosystem: "cargo"
    directory: "/"
    schedule: { interval: "weekly" }
  - package-ecosystem: "npm"
    directory: "/"
    schedule: { interval: "weekly" }
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule: { interval: "weekly" }
```

### [B-015] [Low] [逻辑] package.json:11 / eslint.config.js:10 — lint 仅覆盖 src 目录

**描述**：lint 脚本 `"lint": "eslint src"`（package.json:11）仅检查 `src` 目录，根目录的构建配置 TypeScript 文件未被覆盖：`vite.config.ts`、`vitest.config.ts`、`eslint.config.js`。这些文件中的语法错误、未使用变量等问题不会被 CI 的 `npm run lint` 步骤捕获，需等到 `tsc --noEmit`（仅做类型检查，不查代码风格）或运行时才暴露。

**修复状态**：✅ 已修复于 v4.0 Wave 3I（`package.json` 中 `lint` 脚本从 `"eslint src"` 扩展为 `"eslint src vite.config.ts vitest.config.ts eslint.config.js"`）

**建议**：扩展 lint 范围至根目录配置文件：
```json
"lint": "eslint src vite.config.ts vitest.config.ts eslint.config.js"
```
或在 eslint.config.js 中显式 `files` 匹配根配置文件。

## 优化目标与方案

### v4.0 优先修复（High，1 项）

1. **B-001 dev 配置 asset scope 收窄**：移除 `tauri.dev.conf.json` 中的 `$HOME/**/*`，收窄至 `$APPDATA/mirrorstar/**/*` + `$APPLOCALDATA/mirrorstar/**/*` + `$HOME/Pictures/mirrorstar-test/**/*`；测试需任意路径时通过 `dialog:allow-open` 让用户显式选择。

### v4.0 系统性修复（Medium，7 项）— ✅ 全部已修复于 v4.0 Wave 2F

2. **B-002 tokio features 裁剪**：`full` 改为 `["rt", "rt-multi-thread", "macros", "time", "fs", "sync", "io-util"]`
3. **B-003 release profile 优化**：追加 `[profile.release]` 含 `lto = true` / `codegen-units = 1` / `strip = "symbols"`（暂不设 `panic = "abort"`，避免与 `catch_unwind` 冲突）
4. **B-004 `$schema` 固定 tag**：`dev` 分支改为 `tauri-v2` tag
5. **B-005 版本号统一**：从 `tauri.conf.json` 移除 `version` 字段，统一由 `Cargo.toml` 读取
6. **B-006 npm audit 覆盖 dev 依赖**：增加 `npm audit --audit-level=critical` 步骤，或启用 Dependabot
7. **B-007 release secrets 校验**：release job 起始处 fail-fast 校验 secret 存在性，文档化 secret 清单
8. **B-008 移除 rsproxy.cn 全局替换**：从仓库移除 `.cargo/config.toml` source 替换，改为本地配置或 CI 环境变量

### v4.0 渐进优化（Low，7 项）

9. **B-009 移除无效相对路径**：移除 `"wallpaper/**"` 或改为 `"$RESOURCE/wallpaper/**"`
10. **B-010 CI 编译步骤去冗余**：移除独立 `Build` 步骤，或改为 `--release` 验证 release 编译
11. **B-011 no-console 改为 warn**：与 `no-explicit-any` 一致，logger.ts 通过 overrides 放行
12. **B-012 coverage 补 statements 阈值**：`statements: 70` 与 lines 对齐
13. **B-013 crate-type 裁剪**：移除 `cdylib`/`staticlib`，仅保留 `lib`
14. **B-014 配置 Dependabot**：覆盖 cargo / npm / github-actions 三生态
15. **B-015 lint 范围扩展**：覆盖 `vite.config.ts` / `vitest.config.ts` / `eslint.config.js`
