## 1. 当前状态摘要

### 1.1 模块职责

前端模块负责壁纸应用的全部 UI 渲染与用户交互：壁纸列表渲染（懒加载 + 增量更新 + 事件委托）、配置面板双向同步、显示器下拉填充、拖拽/对话框添加壁纸、预览模态框（含焦点陷阱与安全加固）、IPC 调用封装（带超时与错误脱敏）、应用级状态管理、事件监听器清理。模块采用 Tauri v2 + TypeScript，通过 `main.ts` 集中绑定所有 UI 事件，UI 子模块仅导出渲染/业务函数（v41-F-016 文档化约定）。

## 4. 优化机会（非技术债类改进点）

- **`appState` 响应式化**：state.ts:20-23 注释提及"未来用 class + getter/setter 或 Proxy 实现自动日志/校验/响应式更新"。当前简单对象字面量在状态数量（3 个字段）下足够，但若后续增加更多需校验的状态（如 `currentDisplayId` / `isPlaying`），可评估引入轻量响应式方案（如 `@vue/reactivity` 或自实现 Proxy）。
- **IPC 类型自动生成**：types.ts:25-28 注释提及"引入 ts-rs 或 tauri-specta 从 Rust 结构体自动生成 TS 类型"。当前手动同步在字段数量适中时可控，但 F-TD-005 标记的 `MirrorStarErrorCode` 15 个变体手动维护已有负担，可优先对错误类型引入自动生成。
- **错误处理统一**：当前错误处理分散在 main.ts 的各 catch 块（`log.error + showStatus` 模式重复约 8 处）与 drag-drop.ts 的 `getErrorMessage` 调用。可评估抽取 `handleIpcError(e, statusMsg)` 辅助函数统一"记录原始错误 + 展示脱敏消息"模式。
- **`debounce` 泛型签名优化**：utils.ts:23 的 `debounce<T extends (...args: unknown[]) => void>` 签名要求参数为 `unknown[]`，对 `() => Promise<void>` 的 async 函数可赋值（TS void 返回宽松规则），但调用方传参时仍需注意。可评估改为 `debounce<T extends (...args: any[]) => void>`（牺牲类型安全）或 `debounce<T extends () => void>`（限制无参，覆盖当前所有调用点）。
- **`main.ts` init() 拆分**：main.ts:135-555 的 `init()` 函数长达 420 行，包含 12 个事件绑定 + 6 个 listenWithCleanup + 初始化步骤。v41-F-016 已文档化"未来按 bindDisplayEvents / bindPlaybackEvents / bindWallpaperEvents 拆分"。当前可维护，但事件数继续增长时应实施拆分。
