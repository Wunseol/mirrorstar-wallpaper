### 1.3 CI/CD 概览

- **ci.yml**：双 job（`rust-checks` + `frontend-checks`），运行于 `windows-latest`。Rust 侧执行 test / clippy / fmt / cargo audit / ignored tests；前端侧执行 npm ci / npm audit / build / tsc / lint / test。`cargo test -- --ignored` 步骤 `continue-on-error: true`（共享资源类测试串行执行）。
- **release.yml**：tag `v*` 触发，单 job 复用 CI 全部检查步骤后调用 `tauri-apps/tauri-action@v0` 构建并起草 Release。签名密钥前置校验（fail-fast）。
- **dependabot.yml**：覆盖 cargo / npm / github-actions 三生态，weekly（周一）调度，每生态 `open-pull-requests-limit: 5`。安全补丁由 CI 中 `cargo audit` + `npm audit` 兜底。

## 4. 优化机会（非技术债类改进点）

- **`package.json` 缺少 `engines.node` 声明**：ci.yml:80-83 注释明确说明未声明 `engines`。可添加 `"engines": { "node": ">=20" }` 作为软约束文档化最低运行时要求，与 CI 锁定的 Node 20 对齐。
- **`actions/setup-node@v4` 缓存可扩展至 release.yml**：ci.yml 已用 `cache: npm`，release.yml:39 同样配置，良好。可考虑将 `node-version` 提取为仓库变量（`vars.NODE_VERSION`）避免硬编码。
- **`Swatinem/rust-cache@v2` 版本跟进**：截至审查日 v2 为当前稳定大版本，可关注是否有 v3 发布以利用改进的缓存键策略。
- **`cargo audit` 数据库更新频率**：ci.yml 中 `cargo audit` 使用 `taiki-e/install-action@cargo-audit` 安装最新版，但 advisory 数据库在 runner 上为按需拉取。可考虑在 CI 中增加 `cargo audit --fetch-advisory-db` 频率配置或改用 GitHub Dependabot 安全告警作为补充。
- **前端构建产物体积监控**：vite.config.ts 使用 terser + manualChunks 优化，但未设置 `build.reportCompressedSize` 或 chunk 体积告警阈值，可考虑加入 `chunksizewarninglimit` 防止 vendor chunk 意外膨胀。
- **`tsconfig.json` 未覆盖配置文件**：`include: ["src"]` 排除了 `vite.config.ts` / `vitest.config.ts` / `eslint.config.js`，`npx tsc --noEmit` 仅检查 `src/`。这些配置文件依赖 `process.env` 等 Node 全局，可通过新增 `tsconfig.node.json`（`include: ["*.config.ts"]`）并配置 `references` 实现类型检查覆盖。
