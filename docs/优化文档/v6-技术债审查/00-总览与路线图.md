## 1. 审查范围与方法

### 1.1 审查目标

v5.0 完成后，项目代码质量已达高水平（569+ Rust 测试 / 208+ 前端测试 / clippy 零警告），但多轮修复累积了"修复痕迹"与技术债：死代码、冗余抽象、过时模式、未使用导入、重复实现、过度设计等。v6.0 旨在系统识别并归档这些技术债，为后续清理提供指导纲领。

### 1.3 9 类技术债维度

| 类型 | 定义 | 示例 |
|---|---|---|
| 死代码 | 未使用的函数/结构体/枚举变体/常量/模块导出 | `pub fn foo()` 全项目无调用 |
| 冗余抽象 | 仅一处调用的间接层、过早抽象的 trait、不必要的 wrapper | `trait Foo` 仅 1 个实现且仅 1 处调用 |
| 重复实现 | 同一段逻辑在多处重复 | 校验函数、错误转换、路径处理在多文件复制 |
| 过时模式 | 早期实现的写法已被后续修复改进但未同步到同类代码 | A 模块用新 API，B 模块仍用旧 API |
| 未使用导入 | `use` 语句引入但未使用的项（clippy 未捕获的 `pub use` 重导出） | `pub use foo::Bar` 但外部从未用 Bar |
| 过度设计 | 为已不存在的问题保留的兼容代码、超出当前需求的配置项 | 早期 v1 模式兼容代码、未使用的 feature flag |
| 修复痕迹 | v3.x→v4.0→v5.0 多轮修复留下的过渡性注释、保守的兜底逻辑、引用已失效 spec 的注释 | "v3.5 修复"注释但代码已是 v5.0 状态 |
| 命名一致性 | 同类概念在不同位置命名不一致 | `display_id` / `display_id_str` / `displayId` |
| 注释陈旧 | 注释描述与当前代码行为不符 | 注释说 "TODO" 但代码已完成 |

### 1.4 审查方法

1. 逐文件研读源码与对应测试
2. 按 9 类技术债维度扫描
3. 每项技术债分配 ID（如 `C-TD-001`）、记录位置（文件:行号）、描述、影响、清理建议、预估复杂度
4. 与 v4.0/v5.0 文档对照，标注哪些是 v4.0/v5.0 未覆盖的新发现
5. 按"清理收益 × 实施风险"分级（P0/P1/P2/P3）

## 4. 实施波次计划

### Wave v6-A：P0 高收益低风险批量清理

- **范围**：~98 项 P0 技术债，跨全部 8 个模块
- **特征**：低风险（多为删除死代码/注释改写）、高收益（立即减少代码噪音、消除误导性注释）
- **预计工作量**：~20-30 小时（多数项 <30 min）
- **关键清理类别**：
  1. **死代码删除**（~31 项）：未使用函数/字段/枚举变体/依赖
  2. **修复痕迹清理**（~56 项中的 P0 部分）：移除失效 spec 引用、历史标记前缀
  3. **注释陈旧修正**（~26 项中的 P0 部分）：更新与代码行为不符的注释
  4. **过度设计移除**（~12 项中的 P0 部分）：移除恒返回 Ok 的 Result 包装
- **预计衍生 spec**：`fix-v6-waveA-tech-debt`（可拆分为 `fix-v6-waveA-dead-code` + `fix-v6-waveA-comment-cleanup`）
- **验收标准**：`cargo test --workspace` 全绿 / `cargo clippy` 零警告 / `npm run test` 全绿 / `npm run build` 成功

### Wave v6-B：P1 高收益中风险按模块实施

- **范围**：~50 项 P1 技术债，按模块组织
- **特征**：中风险（涉及跨文件重构、公共 API 变更）、高收益（消除重复实现、移除冗余抽象）
- **关键清理类别**：
  1. **重复实现抽取**：跨文件重复的校验逻辑、错误转换、DOM 操作模式
  2. **冗余抽象移除**：`NamedPipeIpcClient` trait、不必要的 wrapper 函数
  3. **跨模块协调**：config 与 src-tauri 的校验逻辑统一、wallpaper 与 config 的命名统一
- **预计衍生 spec**（每模块 1 个）：
  - `fix-v6-waveB-config-tech-debt`（C-TD-004/008/009/010 等）
  - `fix-v6-waveB-desktop-tech-debt`（D-TD-005/006/007/008 等）
  - `fix-v6-waveB-wallpaper-tech-debt`（W-TD-006/007/008/009 等）
  - `fix-v6-waveB-audio-ipc-tech-debt`（I-TD-002/007/008 等）
  - `fix-v6-waveB-src-tauri-tech-debt`（ST-TD-005/010/011 等）
  - `fix-v6-waveB-frontend-tech-debt`（F-TD-007/008/010/013 等）
  - `fix-v6-waveB-build-tech-debt`（B-TD-004/005/006 等）
- **验收标准**：同 Wave v6-A + 新增测试覆盖重构后的公共函数

### Wave v6-C：P2 中收益谨慎清理

- **范围**：~30 项 P2 技术债
- **特征**：需评估影响、涉及多文件改动或与团队对齐
- **关键清理类别**：
  1. **命名一致性统一**：跨文件变量命名、术语统一
  2. **过时模式同步**：将旧 API 写法同步到新 API 风格
  3. **测试覆盖对齐**：测试与生产路径对齐（如 `PauseReason::TRAY` vs `USER`）
- **预计衍生 spec**：`fix-v6-waveC-{module}-tech-debt`（按需）
- **验收标准**：同 Wave v6-B + 手动验收主流程无回归

### Wave v6-D：P3 长期或低收益择机处理

- **范围**：~23 项 P3 技术债
- **特征**：已记录并接受的权衡、重构成本高、收益分散
- **关键清理类别**：
  1. **已接受权衡记录**：如全局静态量保守策略、`TmpFrameGuard` 简化评估
  2. **长期批量清理**：wp-proc 100+ 历史标记、跨生态版本同步
  3. **索引文档建设**：Bug #N / spec ID 索引文档
- **预计衍生 spec**：`fix-v6-waveD-tech-debt`（择机）
- **验收标准**：无强制验收，按迭代节奏择机处理
