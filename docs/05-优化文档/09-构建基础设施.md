## v4.0 审查发现（15 项）及修复状态

> 来源：`.trae/specs/comprehensive-project-review-and-doc-restructure-2026-07-15/findings/10-build-infra.md`
> 严重级别分布：Critical 0 / High 1 / Medium 7 / Low 7
> 维度分布：架构 1 | 逻辑 1 | 错误 1 | 性能 4 | 安全 4 | 可维护性 4
>
> **核验结论**：下列 15 项已逐一对照当前 `Cargo.toml` / `package.json` / `vite.config.ts` / `vitest.config.ts` / `eslint.config.js` / `checks.yml` / `release.yml` / `.cargo/config.toml` / `tauri.conf.json` 等真实配置核实。**15 项全部已修复（✅）**，无仍未修复项。

### [B-001] [High] [安全] dev 配置 asset scope 含 `$HOME/**/*` 过度宽松 ✅ 已修复

**描述**：v3.x dev 配置（tauri.dev.conf.json）的 `assetProtocol.scope.allow` 含 `"$HOME/**/*"`，将整个用户主目录纳入可访问范围，与 base 配置"仅允许 `$APPDATA/mirrorstar/**/*`"的最小化原则相悖。

**修复状态**：✅ 已修复。当前 `tauri.dev.conf.json` 文件已不存在（Glob 无匹配），base `tauri.conf.json` 亦无 `assetProtocol` 配置——asset 协议整体被移除（见 Cargo.toml `tauri` 依赖移除 `protocol-asset` feature 注释，前端全面切换自定义 wpfile 协议），`$HOME` 全量读取的攻击面已彻底消除。

### [B-002] [Medium] [性能] tokio `full` features 拉入未使用子模块 ✅ 已修复于 v4.0 Wave 2F

**描述**：workspace 级 `tokio = { version = "1", features = ["full"] }` 启用全部 features，拉入大量未被使用的子模块及传递依赖，显著增加编译时间与二进制体积。

**修复状态**：✅ 已修复。当前 `Cargo.toml` `tokio = { version = "1.52", features = ["rt", "rt-multi-thread", "macros", "time", "fs", "sync", "io-util"] }`，已从 `full` 精简为按需启用，并进一步收紧到 minor 级锁定（v16-D-013）。

### [B-003] [Medium] [性能] 缺少 [profile.release] 优化配置 ✅ 已修复于 v4.0 Wave 2F

**描述**：workspace 根 Cargo.toml 未定义 `[profile.release]`，release 二进制偏大且未剥离调试符号，16 个 codegen 单元阻碍跨函数优化。

**修复状态**：✅ 已修复。当前 `Cargo.toml` `[profile.release]` 已配置 `lto = true` / `codegen-units = 1` / `strip = "symbols"`，并额外设置 `panic = "abort"`（附注释说明壁纸应用无需 panic 恢复，已评估与 `catch_unwind` 的取舍）。

### [B-004] [Medium] [可维护性] `$schema` 指向 Tauri dev 分支 ✅ 已修复于 v4.0 Wave 2F

**描述**：`$schema` 指向 `dev` 分支，schema 随时变动，可能引入未发布字段或与稳定版行为不一致。

**修复状态**：✅ 已修复。当前 `tauri.conf.json` `$schema` 锁定 `https://raw.githubusercontent.com/tauri-apps/tauri/tauri-v2.11.2/crates/tauri-config-schema/schema.json`，固定到已发布 tag。

### [B-005] [Medium] [可维护性] 版本号双处硬编码 ✅ 已修复于 v4.0 Wave 2F

**描述**：版本号 `"0.1.0"` 在 `Cargo.toml` 与 `tauri.conf.json` 两处独立硬编码，发版时极易遗漏其一。

**修复状态**：✅ 已修复。当前 `tauri.conf.json` 已移除独立 `version` 字段，统一由 `Cargo.toml` 的 `workspace.package.version` 作为唯一来源。

### [B-006] [Medium] [安全] npm audit `--omit=dev` 不检查 devDependencies ✅ 已修复于 v4.0 Wave 2F

**描述**：`npm audit --omit=dev --audit-level=high` 仅检查生产依赖，devDependencies（vite/vitest/eslint 等）漏洞不被检查，构建工具链供应链风险完全绕过 CI 审计。

**修复状态**：✅ 已修复。当前 `checks.yml` frontend-checks 增加独立步骤 `npm audit --audit-level=critical`（dev 依赖、critical 级非 fatal），与生产依赖审计并行执行。

### [B-007] [Medium] [错误处理] release secrets 未校验存在性 ✅ 已修复于 v4.0 Wave 2F

**描述**：`tauri-action` 无条件注入签名 secret，若仓库未配置（fork/误删/新成员首发），会在完整编译后才失败或静默产出未签名包。

**修复状态**：✅ 已修复。当前 `release.yml` 新增 `verify-secrets` job，通过 env 注入并在 `run` 中对 `TAURI_SIGNING_PRIVATE_KEY` / `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 做 `-z` 判空 fail-fast，且 `checks` job `needs: verify-secrets`。

### [B-008] [Medium] [性能] rsproxy.cn 镜像提交入库影响 CI ✅ 已修复于 v4.0 Wave 2F

**描述**：`.cargo/config.toml` 将 crates.io 全局替换为 rsproxy.cn，对 GitHub Actions 美国 runner 造成跨地域延迟与单一故障点，且非中国区贡献者被迫使用国内镜像。

**修复状态**：✅ 已修复。当前 `.cargo/config.toml` 已移除 source 替换，仅保留 `[net] git-fetch-with-cli = true`；文件注释说明不配置镜像的理由，并给出开发者用户级配置说明（v6 B-TD-018 已清理 fix-marker 编号，保留决策理由）。

### [B-009] [Low] [安全] dev scope `"wallpaper/**"` 相对路径解析基准不明 ✅ 已修复

**描述**：dev scope 中的相对路径 `"wallpaper/**"` 解析基准未文档化，属无效/误导性配置。

**修复状态**：✅ 已修复（依赖 B-001）。dev 配置文件已整体移除，`tauri.conf.json` 亦无 assetProtocol scope，该无效条目不复存在。

### [B-010] [Low] [性能] cargo build + cargo test 冗余步骤 ✅ 已修复于 v4.0 Wave 3I

**描述**：`rust-checks` job 依次执行 `cargo build --workspace` 与 `cargo test --workspace`，`cargo test` 已隐含编译，前一步为冗余步骤。

**修复状态**：✅ 已修复。当前 `checks.yml` rust-checks 无独立 `Build` 步骤，`Test` 步骤注释明确"cargo test 已隐含编译，无需独立 Build 步骤"。

### [B-011] [Low] [可维护性] eslint `no-console: off` 与注释自相矛盾 ✅ 已修复于 v4.0 Wave 3I

**描述**：注释声明"不再直接使用 console"但规则设为 `"off"`（零约束），与 `no-explicit-any: warn` 的渐进收紧策略不一致。

**修复状态**：✅ 已修复。当前 `eslint.config.js` `"no-console": "warn"`，并新增 overrides 对 `src/scripts/utils/logger.ts`、`src/scripts/state.ts` 放行（注释说明放行理由，配合 lint 脚本 `--max-warnings 0`）。

### [B-012] [Low] [可维护性] vitest coverage 缺 `statements` 阈值 ✅ 已修复于 v4.0 Wave 3I

**描述**：coverage 阈值定义 lines/branches/functions 三项，缺 `statements`，语句覆盖门禁存在盲区。

**修复状态**：✅ 已修复。当前 `vitest.config.ts` coverage.thresholds 为 `lines: 70 / branches: 70 / functions: 70 / statements: 70`（四项齐全，且 branches 由 60 对齐提升至 70）。

### [B-013] [Low] [架构] src-tauri `crate-type` 含无用 cdylib/staticlib ✅ 已修复于 v4.0 Wave 3I

**描述**：`[lib]` 声明 `crate-type = ["lib", "cdylib", "staticlib"]`，cdylib/staticlib 在纯 Windows 桌面场景无用，增加编译时间与 target 目录体积。

**修复状态**：✅ 已修复。当前 `src-tauri/Cargo.toml` `crate-type = ["lib"]`，注释保留裁剪理由。

### [B-014] [Low] [可维护性] 未配置 Dependabot ✅ 已修复于 v4.0 Wave 3I

**描述**：`.github/` 下仅有 ci.yml 与 release.yml，依赖更新完全依赖人工 bump。

**修复状态**：✅ 已修复。`.github/dependabot.yml` 已存在，覆盖 cargo / npm / github-actions 三生态，weekly 调度，`open-pull-requests-limit: 5`。

### [B-015] [Low] [逻辑] lint 仅覆盖 src 目录 ✅ 已修复于 v4.0 Wave 3I

**描述**：`"lint": "eslint src"` 仅检查 src，根目录构建配置（vite.config.ts / vitest.config.ts / eslint.config.js）不被覆盖。

**修复状态**：✅ 已修复。当前 `package.json` `"lint": "eslint src vite.config.ts vitest.config.ts eslint.config.js --max-warnings 0"`。

### v6 优化机会（非技术债类改进点）

- **`package.json` 缺少 `engines.node` 声明**：可添加 `"engines": { "node": ">=20" }` 作为软约束文档化最低运行时要求，与 CI 锁定的 Node 20 对齐。
- **`actions/setup-node@v4` 缓存**：ci.yml/release.yml 已用 `cache: npm`，良好；可考虑将 `node-version` 提取为仓库变量（`vars.NODE_VERSION`）避免硬编码。
- **`Swatinem/rust-cache@v2` 版本跟进**：关注是否有 v3 发布以利用改进的缓存键策略。
- **`cargo audit` 数据库更新频率**：可考虑 `cargo audit --fetch-advisory-db` 频率配置或依赖 GitHub Dependabot 安全告警兜底。
- **前端构建产物体积监控**：vite.config.ts 使用 terser + manualChunks 优化但未设 `chunksizeWarningLimit`，可加入防止 vendor chunk 意外膨胀。
- **`tsconfig.json` 未覆盖配置文件**：`include: ["src"]` 排除 vite/vitest/eslint 配置文件，`npx tsc --noEmit` 仅检查 `src/`。可新增 `tsconfig.node.json`（`include: ["*.config.ts"]`）并通过 `references` 覆盖。
