## 4. 功能需求分析

### 4.1 壁纸渲染路径（v3.0 修正）

壁纸渲染采用 **双模式分发**，由 `WallpaperEngine::set_wallpaper`（`crates/mirrorstar-core/src/wallpaper/mode_dispatch.rs`）按壁纸来源与类型决定使用 **Native** 还是 **WorkerW** 模式：

| 类型 | 来源 | 原生格式支持 | 模式 |
|------|------|--------------|------|
| Image | File | 是 | **Native**（零资源占用，不嵌入 WorkerW） |
| Image | File | 否 | **WorkerW**（GDI 渲染） |
| Image | Url | — | **WorkerW**（仅 File 支持 Native） |
| Gif / Video / Web | * | — | **WorkerW** |

其中 `native_wallpaper::is_native_supported` 判定的原生支持格式为：**jpg / jpeg / png / bmp / tif / tiff / dib**。其余图片格式（如 **WebP**）回退到 WorkerW 渲染路径。

### 4.2 Lively Wallpaper 功能全景

以下为 Lively Wallpaper 的完整功能列表及其在 MirrorStar 中的取舍决策。

### 4.3 保留功能

| 功能 | 说明 | 保留理由 |
|------|------|----------|
| 视频壁纸 | 通过 mpv 播放视频文件作为壁纸 | 核心功能，用户最常用的壁纸类型 |
| GIF 壁纸 | 播放 GIF 动图作为壁纸 | 核心功能，轻量级动态壁纸 |
| 网页壁纸 | 通过 WebView2 渲染网页作为壁纸 | 核心功能，支持 Shadertoy、网页动画等丰富内容 |
| 静态图片壁纸 | 设置静态图片为壁纸 | 基础功能，用户期望的最低支持 |
| 桌面集成 | 通过 WorkerW 将壁纸嵌入桌面 | 技术核心，实现壁纸在桌面图标下方显示 |
| 多显示器支持 | 为不同显示器设置不同壁纸 | 实用功能，多显示器用户刚需 |
| 暂停/恢复 | 检测全屏应用自动暂停壁纸 | 性能关键，游戏/全屏应用时释放资源 |
| 系统托盘 | 最小化到系统托盘运行 | 壁纸软件必备，后台运行不占任务栏 |
| 配置管理 | 保存和加载用户设置 | 基础功能，持久化用户偏好 |
| 拖放设置壁纸 | 拖拽文件到窗口设置壁纸 | 易用性功能，降低操作门槛 |

### 4.4 去除功能

| 功能 | 去除理由 |
|------|----------|
| Unity 壁纸 | 用户群体极小，Unity 运行时体积庞大（>100MB），与轻量化目标严重冲突 |
| Godot 壁纸 | 用户群体极小，Godot 运行时体积较大，与轻量化目标冲突 |
| BizHawk 模拟器壁纸 | 极其小众的需求，模拟器依赖复杂，维护成本极高 |
| YouTube/流媒体壁纸 | 依赖 youtube-dl/yt-dlp 等外部工具，网络流媒体增加复杂度和资源消耗，用户可直接下载视频后使用视频壁纸 |
| 壁纸创建器 | 非核心功能，用户可使用外部工具（如 VS Code、Shadertoy）创建壁纸内容 |
| 自动更新 | 安全风险（供应链攻击），增加复杂度，用户可手动更新或通过包管理器更新 |
| 多语言国际化 (i18n) | UI 仅支持中文界面（简体中文），代码结构预留 i18n 扩展点 |
| 壁纸库 GIF 预览 | GIF 预览需要解码并缓存帧数据，内存占用高；改用静态缩略图 |
| 按进程应用程序规则 | 全屏检测暂停已覆盖主要场景；按进程规则可后续版本添加 |

## 5. 功能性需求

> 优先级符号：P0（核心）/ P1（重要）/ P2（增强）。🔧 表示当前未实现或部分实现，需未来改进。

### 5.1 壁纸管理

| 需求 ID | 需求名称 | 优先级 | 描述 |
|---------|----------|--------|------|
| FR-001 | 视频壁纸播放 | P0 | 支持通过外部 mpv.exe 子进程播放 MP4/AVI/MKV/WebM/MOV/FLV 等常见视频格式作为动态壁纸，支持硬件加速解码（mpv `--hwdec=auto`）。mpv.exe 通过命名管道（`\\.\pipe\mirrorstar-mpv-*`）接收 mpv 原生 JSON IPC 命令控制 |
| FR-002 | GIF 壁纸播放 | P0 | 支持播放 GIF 动图作为动态壁纸，支持 GIF 循环播放（GDI + WM_TIMER 驱动，含 4 种内存管理策略） |
| FR-003 | 网页壁纸渲染 | P0 | 支持通过 WebView2 渲染 HTML/CSS/JavaScript 网页作为壁纸。网页壁纸由 `mirrorstar-wp-proc.exe` 子进程承载，主进程通过命名管道 `\\.\pipe\mirrorstar-wp-*` 与 wp-proc 通信 |
| FR-004 | 静态图片壁纸 | P0 | 支持设置 JPG/JPEG/PNG/BMP/TIF/TIFF/DIB/WebP 等静态图片为壁纸。其中 jpg/jpeg/png/bmp/tif/tiff/dib 使用 Windows 原生壁纸 API（`SystemParametersInfoW` + 注册表），零资源占用；WebP 等不被原生 API 支持的格式回退到 WorkerW 渲染路径（GDI 绘制） |
| FR-005 | 壁纸切换 | P0 | 支持在已添加的壁纸之间切换（含同显示器 Native ↔ WorkerW 模式切换），切换过程平滑无闪烁（桌面无黑屏闪烁，旧壁纸保持显示直到新壁纸就绪） |
| FR-006 | 壁纸删除 | P1 | 支持从壁纸库中移除壁纸，可选是否删除源文件 |
| FR-007 | 壁纸信息显示 | P2 | 显示壁纸的文件名、类型、分辨率、文件大小等基本信息 |
| FR-034 | 壁纸缩放模式 | P1 | 支持壁纸缩放/适配模式设置：填充（Fill）、适应（Fit）、拉伸（Stretch）、居中（Center）。Image/GIF 通过 PostMessageW 触发重绘；Video 通过 mpv 启动参数设置（运行时仅记录，需重启 mpv 生效）；Web 仅记录模式（WebView2 自行处理渲染） |

### 5.2 桌面集成

| 需求 ID | 需求名称 | 优先级 | 描述 |
|---------|----------|--------|------|
| FR-008 | WorkerW 桌面嵌入 | P0 | 将壁纸窗口嵌入 Windows 桌面的 WorkerW 层，使壁纸显示在桌面图标下方。仅动态壁纸（视频/GIF/网页）与不支持原生 API 的静态图片需要 WorkerW 嵌入；jpg/jpeg/png/bmp/tif/tiff/dib 静态壁纸使用 Windows 原生 API，无需 WorkerW |
| FR-009 | 壁纸窗口定位 | P0 | 壁纸窗口精确定位到桌面工作区，覆盖整个桌面背景区域。WorkerW 异步初始化（后台线程），不阻塞启动流程 |
| FR-010 | 桌面图标交互 | P0 | 壁纸运行时，桌面图标仍可正常点击、选择、拖动 |
| FR-035 | Explorer 重启检测 | P1 | 检测 Windows Explorer 重启事件，自动重新嵌入壁纸窗口到新的 WorkerW 层（TaskbarCreated 事件驱动即时恢复；5 分钟轮询检测 WorkerW 句柄有效性作为兜底） |
| FR-039 | DPI 缩放适配 | P1 | 壁纸窗口在 Per-Monitor DPI V2 模式下正确显示，支持不同 DPI 缩放比例的多显示器环境，DPI 变更时自动调整壁纸尺寸（处理 `WM_DPICHANGED`） |

### 5.3 多显示器

| 需求 ID | 需求名称 | 优先级 | 描述 |
|---------|----------|--------|------|
| FR-011 | 多显示器识别 | P0 | 自动检测并列出系统中所有连接的显示器 |
| FR-012 | 独立壁纸设置 | P0 | 支持为每个显示器独立设置不同的壁纸 |
| FR-013 | 显示器热插拔 | P1 | 支持显示器热插拔事件的检测和自动适配。当前已处理 `WM_DISPLAYCHANGE` 消息：显示器分辨率切换 / 热插拔时重新查询实际屏幕尺寸并调整壁纸窗口定位（`gdi_base.rs` / `invalidate_screen_size_cache`），壁纸窗口随分辨率变化自适应；支持新增显示器时检测到显示配置变更。🔧 新增显示器时是否自动为新建显示器设置壁纸、以及完整的显示拓扑变更适配仍需进一步验证 |
| FR-014 | 跨显示器壁纸 | P2 | 可选将单个壁纸跨所有显示器拉伸显示。🔧 未实现，未来改进 |

### 5.4 暂停与恢复

| 需求 ID | 需求名称 | 优先级 | 描述 |
|---------|----------|--------|------|
| FR-015 | 全屏应用检测 | P0 | 检测到全屏应用（如游戏、全屏视频）运行时自动暂停所有壁纸，退出全屏时恢复所有壁纸。采用**事件驱动**机制（`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`，非轮询），通过 `pause_all_fast` / `try_pause_all_fast` 快速通道实现。注：当前为全局暂停，按显示器独立暂停为未来改进项 |
| FR-016 | 手动暂停/恢复 | P0 | 支持用户手动暂停和恢复壁纸播放 |
| FR-017 | 暂停时静态帧 | P1 | 壁纸暂停时显示当前帧的静态画面，而非黑屏或隐藏 |
| FR-018 | 音频暂停 | P1 | 壁纸暂停时同步静音，恢复时恢复音量 |
| FR-032 | 电池供电暂停 | P2 | 检测到系统切换到电池供电时自动暂停壁纸播放（需用户在设置中启用 `pause.pause_on_battery`），接通电源后自动恢复。基于 `WM_POWERBROADCAST` / `PBT_APMPOWERSTATUSCHANGE` 事件实现（`src-tauri/src/platform/power.rs`） |

### 5.5 系统托盘

| 需求 ID | 需求名称 | 优先级 | 描述 |
|---------|----------|--------|------|
| FR-019 | 托盘图标 | P0 | 程序启动时仅创建系统托盘图标，不创建主窗口。托盘菜单文本切换暂停/恢复状态（图标本身不随状态变化，仅菜单项文本反映当前状态）。主窗口按需创建：用户点击托盘图标时创建窗口，关闭窗口时隐藏窗口（hide）以保留 WebView2 实例，WebView2 延迟创建 |
| FR-020 | 托盘菜单 | P0 | 右键托盘图标弹出菜单，包含：打开（打开主窗口，按需创建 WebView2 窗口）、暂停壁纸/恢复壁纸（切换壁纸播放状态）、退出。注：更丰富的托盘菜单（音量控制子菜单、显示器壁纸信息子菜单）为未来改进项 |
| FR-021 | 关闭隐藏窗口 | P0 | 关闭主窗口时隐藏窗口（hide）以保留 WebView2 实例，便于快速恢复（`prevent_close + hide()`）。再次打开时直接 show，无需重新创建 WebView2 |
| FR-022 | 开机自启 | P1 | 支持设置开机自动启动（tauri-plugin-autostart，写入注册表启动项，无需管理员权限） |
| FR-040 | 单实例运行 | P0 | 程序同时只能运行一个实例，重复启动时提示"镜星壁纸已在运行中"并退出新实例（通过 Windows 命名互斥体 `MirrorStarWallpaper_SingleInstance` 实现） |

### 5.6 配置管理

| 需求 ID | 需求名称 | 优先级 | 描述 |
|---------|----------|--------|------|
| FR-023 | 配置持久化 | P0 | 用户设置（当前壁纸、音量、暂停策略等）持久化保存，重启后恢复（TOML 格式） |
| FR-024 | 壁纸库管理 | P0 | 维护用户添加的壁纸列表，包含壁纸路径、类型、缩略图等信息 |
| FR-025 | 音量控制 | P1 | 支持调节视频/网页壁纸的音频音量，包括全局静音（通过 Core Audio API 控制壁纸子进程音量） |
| FR-026 | 播放速度 | P2 | 支持调节视频和 GIF 壁纸的播放速度（默认 1.0 倍速，范围 0.25~4.0）。视频壁纸通过 mpv IPC set_speed 命令实现；GIF 壁纸通过 `GifCommand::SetSpeed` 调整定时器间隔实现 |
| FR-027 | 配置文件路径 | P2 | 配置文件存储在 `%APPDATA%/mirrorstar/` 目录下 |
| FR-036 | 壁纸搜索 | P2 | 支持按文件名在壁纸库中实时搜索过滤壁纸，不区分大小写 |
| FR-037 | 配置热重载 | P2 | 支持配置文件的热重载，用户通过外部编辑器修改配置文件后，程序自动检测变更并应用新配置（部分配置项立即生效，部分需重启） |
| FR-038 | WebView2 数据目录管理 | P2 | 每个 WebView2 壁纸实例使用独立的用户数据目录，壁纸删除时清理对应数据目录，定期清理超过 30 天未使用的数据目录。🔧 未实现，未来改进（WebView2 使用默认数据目录） |
