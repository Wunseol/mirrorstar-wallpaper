## 8. 用例描述

### UC-001：设置视频壁纸

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-001 |
| 用例名称 | 设置视频壁纸 |
| 参与者 | 用户 |
| 前置条件 | 程序已启动，系统托盘图标可见 |
| 基本流程 | 1. 用户打开主窗口<br>2. 用户通过文件选择对话框或拖放方式添加视频文件<br>3. 系统识别文件为视频类型<br>4. 系统生成首帧缩略图并添加到壁纸库<br>5. 系统启动 mpv 子进程播放视频（mpv `--hwdec=auto`，命名管道 `\\.\pipe\mirrorstar-mpv-*` 承载原生 JSON IPC）<br>6. 系统将 mpv 窗口嵌入 WorkerW 层<br>7. 视频壁纸在桌面背景显示 |
| 替代流程 | 3a. 文件格式不支持：系统提示"不支持的文件格式"<br>5a. mpv 启动失败：系统显示错误信息，回退到上一壁纸 |
| 后置条件 | 视频壁纸在桌面背景播放，壁纸库中新增该壁纸 |
| 非功能约束 | 壁纸切换时间标称 < 1 秒（NFR-007；⚠️ 实测约 3s，待优化/待复测），CPU 占用 < 5%（NFR-004） |

### UC-002：设置网页壁纸

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-002 |
| 用例名称 | 设置网页壁纸 |
| 参与者 | 用户 |
| 前置条件 | 程序已启动，系统已安装 WebView2 Runtime |
| 基本流程 | 1. 用户打开主窗口<br>2. 用户添加本地 HTML 文件或输入 URL<br>3. 系统识别为网页类型<br>4. 系统生成默认缩略图并添加到壁纸库<br>5. 系统以壳 exe 的 `--wp-proc` 模式启动子进程（`mirrorstar-wp-proc` 库 crate 由壳 exe 承载），通过 WebView2 渲染网页<br>6. 系统将 WebView2 窗口嵌入 WorkerW 层<br>7. 网页壁纸在桌面背景显示 |
| 替代流程 | 5a. WebView2 不可用：系统提示"需要安装 WebView2 Runtime"<br>5b. URL 无法访问：系统显示加载失败提示 |
| 后置条件 | 网页壁纸在桌面背景渲染，壁纸库中新增该壁纸。主进程通过命名管道 `\\.\pipe\mirrorstar-wp-*`（高熵 UUID）与 wp-proc 通信，实现崩溃隔离 |
| 非功能约束 | 活跃态主进程内存 < 50MB（NFR-002，不含 WebView2 子进程） |

### UC-003：全屏应用自动暂停

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-003 |
| 用例名称 | 全屏应用自动暂停 |
| 参与者 | 系统 |
| 前置条件 | 壁纸正在播放 |
| 基本流程 | 1. 系统监测到全屏应用程序启动（`SetWinEventHook` / `EVENT_SYSTEM_FOREGROUND` 事件）<br>2. 系统通过 `pause_all_fast` 暂停所有壁纸播放<br>3. 壁纸显示当前帧的静态画面<br>4. 系统切换托盘菜单文本为"恢复壁纸"（图标本身不变化）<br>5. 全屏应用退出<br>6. 系统自动恢复所有壁纸播放<br>7. 系统切换托盘菜单文本为"暂停壁纸"（图标本身不变化） |
| 替代流程 | 2a. 用户已手动暂停：不重复操作<br>5a. 用户在全屏期间手动恢复：尊重用户操作，恢复播放 |
| 后置条件 | 壁纸暂停时 CPU 占用 < 0.1%（NFR-003） |
| 非功能约束 | 暂停响应时间 < 500ms（NFR-019） |

### UC-005：多显示器独立壁纸设置

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-005 |
| 用例名称 | 多显示器独立壁纸设置 |
| 参与者 | 用户 |
| 前置条件 | 系统连接了多个显示器 |
| 基本流程 | 1. 用户打开主窗口<br>2. 系统显示所有已连接的显示器列表<br>3. 用户选择目标显示器（仅在"每屏独立"排列下有效，其他排列下该选择置灰）<br>4. 用户为该显示器选择壁纸<br>5. 系统在目标显示器上设置指定壁纸<br>6. 其他显示器壁纸不受影响 |
| 替代流程 | 2a. 仅一个显示器：跳过选择步骤，直接设置壁纸<br>5a. 排列为"全部相同"：一张壁纸在各屏顺序各 apply 一次（N 渲染器，换图窗口期各屏瞬时新/旧混杂为已知接受项）<br>5b. 排列为"跨屏拉伸"：单个跨屏渲染器贯通虚拟桌面，仅 1 次 apply |
| 后置条件 | 目标显示器显示新壁纸，其他显示器不变（"每屏独立"排列下） |
| 非功能约束 | 每个显示器的壁纸进程独立管理。多屏排列语义详见 UC-019 与术语表 `Arrangement` |

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-006 |
| 用例名称 | 系统托盘操作 |
| 参与者 | 用户 |
| 前置条件 | 程序已启动 |
| 基本流程 | 1. 程序启动后在系统托盘显示图标（不创建主窗口）<br>2. 用户右键托盘图标<br>3. 系统显示上下文菜单：打开主窗口 / 暂停或恢复壁纸 / 纯净壁纸（勾选） / 退出<br>4. 用户选择菜单项<br>5. 系统执行对应操作 |
| 替代流程 | 2a. 单击托盘图标：按主窗口可见性状态切换（不判断系统前台）——可见且未最小化则隐藏；最小化则还原并置前聚焦；已隐藏则显示（居中到鼠标所在显示器）并置前聚焦（300ms 内重复点击只生效一次）<br>4a. 用户选择"打开主窗口"：壳侧按需 spawn 原生 UI 子进程 `mirrorstar-ui`（Slint），确保窗口可见并置前聚焦（已可见仅置前聚焦、最小化则还原）<br>4b. 用户选择"退出"：程序保存配置后退出 |
| 后置条件 | 对应操作已执行 |
| 非功能约束 | 托盘菜单响应时间 < 200ms（NFR-020） |

### UC-008：设置静态图片壁纸

| 项目 | 内容 |
|------|------|

| 用例名称 | 设置静态图片壁纸 |
| 参与者 | 用户 |

| 后置条件 | 图片壁纸在桌面背景显示，壁纸库中新增该壁纸 |

### UC-009：删除壁纸

|------|------|
| 用例 ID | UC-009 |
| 用例名称 | 删除壁纸 |
| 参与者 | 用户 |
| 前置条件 | 壁纸库中至少有一个壁纸 |

### UC-013：Explorer 重启后自动恢复

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-013 |
| 用例名称 | Explorer 重启后自动恢复 |
| 参与者 | 系统 |
| 前置条件 | 壁纸正在播放 |
| 基本流程 | 1. Windows Explorer 进程重启（用户手动重启或系统更新）<br>2. 系统检测到 WorkerW 窗口句柄失效<br>3. 系统重新查找 Progman 窗口<br>4. 系统发送 `0x052C` 消息创建新的 WorkerW<br>5. 系统将所有活跃壁纸窗口重新嵌入新的 WorkerW<br>6. 壁纸恢复正常显示 |
| 替代流程 | 3a. WorkerW 失效兜底：5 分钟轮询检测 WorkerW 句柄有效性（`is_workerw_valid`），失效时调用 `check_and_reinitialize` 重新初始化。同时 `TaskbarCreated` 事件驱动即时检测（注册窗口消息，收到时立即重新初始化） |
| 后置条件 | 壁纸在新的 WorkerW 中正常显示 |
| 非功能约束 | Explorer 重启后壁纸恢复时间 < 5 秒（`TaskbarCreated` 事件驱动即时恢复；5 分钟轮询作为兜底） |

### UC-014：电池供电自动暂停

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-014 |
| 用例名称 | 电池供电自动暂停 |
| 参与者 | 系统 |
| 前置条件 | 壁纸正在播放，用户已启用"电池供电暂停"设置（`pause.pause_on_battery`） |
