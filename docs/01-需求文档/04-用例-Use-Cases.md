## 8. 用例描述

### UC-001：设置视频壁纸

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-001 |
| 用例名称 | 设置视频壁纸 |
| 参与者 | 用户 |
| 前置条件 | 程序已启动，系统托盘图标可见 |
| 基本流程 | 1. 用户打开主窗口<br>2. 用户通过文件选择对话框或拖放方式添加视频文件<br>3. 系统识别文件为视频类型<br>4. 系统生成首帧缩略图并添加到壁纸库<br>5. 系统创建隐藏视频宿主窗口，并以 `--wid=<宿主>` 启动 mpv 子进程（mpv `--hwdec=auto`，命名管道 `\\.\pipe\mirrorstar-mpv-*` 承载原生 JSON IPC；mpv 只创建宿主内 `WS_CHILD` 子窗口，不产生顶层窗口）<br>6. 系统将视频宿主窗口嵌入桌面壁纸层（raised desktop 下为 Progman 的 layered 子窗口，旧层级为 WorkerW）<br>7. 视频壁纸在桌面背景显示 |
| 替代流程 | 3a. 文件格式不支持：系统提示"不支持的文件格式"<br>5a. mpv 启动失败：系统显示错误信息；手动设为壁纸的三阶段流程已先关闭旧壁纸，需用户重试或重新设置（不自动回滚） |
| 后置条件 | 视频壁纸在桌面背景播放，壁纸库中新增该壁纸 |
| 非功能约束 | 壁纸切换时间标称 < 1 秒（NFR-007；历史约 3s，待复测），CPU 占用 < 5%（NFR-004） |

### UC-002：设置网页壁纸

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-002 |
| 用例名称 | 设置网页壁纸 |
| 参与者 | 用户 |
| 前置条件 | 程序已启动，系统已安装 WebView2 Runtime |
| 基本流程 | 1. 用户打开主窗口<br>2. 用户添加本地 `.html`/`.htm` 文件<br>3. 系统识别为网页类型<br>4. 系统添加到壁纸库（网页类型不生成缩略图，UI 显示类型占位）<br>5. 系统以壳 exe 的 `--wp-proc` 模式启动子进程（`mirrorstar-wp-proc` 库 crate 由壳 exe 承载），通过 WebView2 渲染网页<br>6. 系统将 WebView2 窗口嵌入桌面层（WorkerW；Win11 raised desktop 下为 Progman 的 layered 子窗口）<br>7. 网页壁纸在桌面背景显示 |
| 替代流程 | 2a. 远程 http/https 默认拒绝（`ALLOWED_REMOTE_DOMAINS` 为空，仅 `localhost`/`127.0.0.1` 放行）；URL 输入当前未实现<br>5a. WebView2 缺失：系统提示网页壁纸不可用（无内置引导安装）<br>5b. 本地页面加载失败：系统显示加载失败提示 |
| 后置条件 | 网页壁纸在桌面背景渲染，壁纸库中新增该壁纸。主进程通过命名管道 `\\.\pipe\mirrorstar-wp-*`（高熵 UUID）与 wp-proc 通信，实现崩溃隔离 |
| 非功能约束 | 活跃态主进程内存 < 50MB（NFR-002，不含 WebView2 子进程） |

### UC-003：全屏应用自动处置

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-003 |
| 用例名称 | 全屏应用自动处置（暂停/终止/持续） |
| 参与者 | 系统 |
| 前置条件 | 壁纸正在播放 |
| 基本流程 | 1. 系统监测到全屏应用程序启动（`SetWinEventHook` / `EVENT_SYSTEM_FOREGROUND` 事件）<br>2. 系统按 `pause.fullscreen_action` 处置所有壁纸：默认 `terminate`（终止子进程）、可选 `pause`（暂停）、`none`（不处置）<br>3. `pause` 下壁纸显示当前帧的静态画面，`terminate` 下渲染器子进程已退出，`none` 下壁纸继续播放<br>4. 系统切换托盘菜单文本为"恢复壁纸"（图标本身不变化）<br>5. 全屏应用退出<br>6. 系统按处置方式恢复：`terminate` 冷启动恢复、`pause` 即时恢复、`none` 无需恢复<br>7. 系统切换托盘菜单文本为"暂停壁纸"（图标本身不变化） |
| 替代流程 | 2a. 用户已手动暂停：不重复操作<br>5a. 用户在全屏期间手动恢复：尊重用户操作，恢复播放 |
| 后置条件 | 退出全屏后壁纸按处置方式恢复（`terminate` 冷启动 / `pause` 即时 / `none` 持续播放）；`terminate`/`pause` 下壁纸 CPU 占用 < 0.1%（NFR-003） |
| 非功能约束 | `pause` 策略下暂停响应时间 < 500ms（NFR-019）；`terminate` 策略为子进程终止耗时，待复测 |

### UC-004：拖放添加壁纸

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-004 |
| 用例名称 | 拖放添加壁纸 |
| 参与者 | 用户 |
| 前置条件 | 程序主窗口已打开 |
| 基本流程 | 1. 用户从资源管理器拖拽文件到主窗口<br>2. 系统检测到拖放事件<br>3. 系统识别文件类型（视频/GIF/网页/图片）<br>4. 系统将文件复制进托管目录、添加到壁纸库并异步生成缩略图<br>5. 系统刷新壁纸网格，但不自动切换当前壁纸（用户需点击卡片"设为壁纸"） |
| 替代流程 | 3a. 文件类型不支持：系统提示"不支持的文件类型"<br>3b. 多个文件拖入：逐个串行添加，全部加入壁纸库，不自动设为当前壁纸<br>3c. 重复文件：按规范化路径去重并跳过 |
| 后置条件 | 壁纸库新增壁纸并刷新网格，当前壁纸不变（除非用户另行设为壁纸） |
| 非功能约束 | 支持同时拖入多个文件 |

### UC-005：多显示器独立壁纸设置

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-005 |
| 用例名称 | 多显示器独立壁纸设置 |
| 参与者 | 用户 |
| 前置条件 | 系统连接了多个显示器 |
| 基本流程 | 1. 用户打开主窗口<br>2. 系统显示所有已连接的显示器列表<br>3. 用户选择目标显示器（仅在"每屏独立"排列下有效，其他排列下该选择置灰）<br>4. 用户为该显示器选择壁纸<br>5. 系统在目标显示器上设置指定壁纸<br>6. 其他显示器壁纸不受影响 |
| 替代流程 | 2a. 仅一个显示器：跳过选择步骤，直接设置壁纸<br>5a. 排列为"每屏同图（AllSame）"：一张壁纸在各屏顺序各 apply 一次（N 渲染器，换图窗口期各屏瞬时新/旧混杂为已知接受项）<br>5b. 排列为"跨屏合并（Span）"：单个跨屏渲染器贯通虚拟桌面，仅 1 次 apply |
| 后置条件 | 目标显示器显示新壁纸，其他显示器不变（"每屏独立"排列下） |
| 非功能约束 | 每个显示器的壁纸进程独立管理。多屏排列语义详见 UC-019 与术语表 `Arrangement` |

|------|------|
| 用例 ID | UC-006 |
| 用例名称 | 系统托盘操作 |
| 参与者 | 用户 |
| 前置条件 | 程序已启动 |
| 基本流程 | 1. 程序启动后在系统托盘显示图标（不创建主窗口）<br>2. 用户右键托盘图标<br>3. 系统显示上下文菜单：打开主窗口 / 暂停或恢复壁纸 / 下一张壁纸 / 纯净壁纸（勾选） / 退出<br>4. 用户选择菜单项<br>5. 系统执行对应操作 |
| 替代流程 | 2a. 单击托盘图标：按主窗口可见性状态切换（不判断系统前台）——可见且未最小化则隐藏；最小化则还原并置前聚焦；已隐藏则显示（居中到鼠标所在显示器）并置前聚焦（300ms 内重复点击只生效一次）<br>4a. 用户选择"打开主窗口"：壳侧按需 spawn 原生 UI 子进程 `mirrorstar-ui`（Slint），确保窗口可见并置前聚焦（已可见仅置前聚焦、最小化则还原）<br>4b. 用户选择"下一张壁纸"：调用 `next_wallpaper`，走手动通道即时换图，不受暂停限制<br>4c. 用户选择"退出"：程序保存配置后退出 |
| 后置条件 | 对应操作已执行 |
| 非功能约束 | 托盘菜单响应时间 < 200ms（NFR-020） |

### UC-008：设置静态图片壁纸

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-008 |
| 用例名称 | 设置静态图片壁纸 |
| 参与者 | 用户 |
| 前置条件 | 程序已启动，系统托盘图标可见 |
| 基本流程 | 1. 用户打开主窗口<br>2. 用户通过文件选择对话框或拖放方式添加图片文件（添加入口识别 `jpg/jpeg/png/bmp/webp/tif/tiff/ico`）<br>3. 系统识别文件为图片类型<br>4. 系统生成缩略图并添加到壁纸库<br>5a. **Native 路径**（`jpg/jpeg/png/bmp/tif/tiff/dib`，见 FR-004）：系统调用 Windows 原生壁纸 API（`SystemParametersInfoW` + 注册表）设置壁纸，零渲染器、不嵌入 WorkerW<br>5b. **WorkerW 路径**（`WebP`/`ICO` 等非原生格式）：系统解码图片，通过 GDI 双缓冲渲染到壁纸窗口，嵌入 WorkerW 层<br>6. 图片壁纸在桌面背景显示。注：`.dib` 不在添加入口识别列表，当前无法添加 |
| 替代流程 | 3a. 图片格式不支持：系统提示"不支持的图片格式" |

| 非功能约束 | 图片加载/设置时间 < 500ms |

### UC-009：删除壁纸

| 项目 | 内容 |
|------|------|
| 用例 ID | UC-009 |
| 用例名称 | 删除壁纸 |
| 参与者 | 用户 |
| 前置条件 | 壁纸库中至少有一个壁纸 |
| 基本流程 | 1. 用户在壁纸库中选择要删除的壁纸<br>2. 用户点击删除按钮<br>3. 系统弹出确认浮层，提示"将从库中移除该壁纸并删除源文件，此操作不可撤销"（UI 文案称"源文件"，实际删除的是库内托管副本）<br>4. 用户确认删除<br>5. 若该壁纸正在运行，系统先关闭该壁纸的渲染器/原生壁纸<br>6. 系统从壁纸库中移除该壁纸条目<br>7. 系统回收对应的缩略图文件（无论是否删除托管副本）<br>8. 系统在通过 `data_dir` 边界校验后删除库内托管副本（`data_root/wallpapers/{id}/...`）；用户原始外部文件不会被删除 |
| 替代流程 | 4a. 用户取消：不执行任何变更<br>4b. 命令层 `delete_file=false`：仅移除库条目并回收缩略图，保留托管副本（当前主窗口 UI 未暴露该选项，仅 API 可用）<br>8a. 托管副本删除失败或未通过 `data_dir` 边界校验：库条目与缩略图已移除，托管副本保留并记录日志 |
| 后置条件 | 壁纸从壁纸库中移除，正在运行的渲染器/原生壁纸已关闭，缩略图已回收；托管副本已删除或按 `delete_file=false` 保留；用户原始外部文件不受影响 |
| 非功能约束 | 删除操作不可撤销，需确认对话框 |
