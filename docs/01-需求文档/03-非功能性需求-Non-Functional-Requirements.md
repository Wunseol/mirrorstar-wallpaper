## 6. 非功能性需求

### 6.1 性能需求

| 需求 ID | 需求名称 | 指标 | 验收标准 |
|---------|----------|------|----------|
| NFR-001 | 暂停态内存占用 | 主进程 < 20MB | 壁纸暂停时，主进程工作集内存不超过 20MB。暂停态下 WebView2 主窗口已隐藏（hide），无 WebView2 子进程；GIF 帧数据在暂停时释放（40MB 预算，仅保留当前帧）。⚠️ Debug 实测：2026-06-25 空闲态 22.03MB、2026-07-05 空闲态 22.17MB（均略超）；**待 Release 构建复测以确认是否达标** |
| NFR-002 | 活跃态内存占用 | 主进程 < 50MB | 视频壁纸播放时，主进程工作集内存不超过 50MB（不含 mpv/WebView2 子进程） |
| NFR-003 | 暂停态 CPU 占用 | < 0.1% | 壁纸暂停时，主进程 CPU 占用 < 0.1%（无后台轮询，仅事件驱动；事件驱动全屏检测 SetWinEventHook + PauseSender 快速通道，无轮询线程） |
| NFR-004 | 活跃态 CPU 占用 | < 5% | 视频壁纸播放时，主进程 CPU 占用不超过 5%（硬件解码 mpv --hwdec=auto） |
| NFR-005 | 冷启动时间 | < 2 秒 | 从双击图标到托盘图标出现的时间不超过 2 秒。启动时不创建 WebView2 主窗口，仅初始化托盘图标和壁纸引擎；WorkerW 异步初始化（后台线程），不阻塞启动流程。托盘图标实际出现时间 < 1 秒 |
| NFR-006 | 热启动时间 | < 1.5 秒 | 从托盘打开主窗口的时间不超过 1.5 秒。由于窗口关闭时隐藏（hide），"热启动"只需 show() 恢复窗口，WebView2 实例已保留，恢复时间 < 100ms |
| NFR-007 | 壁纸切换时间 | < 1 秒 | 从选择壁纸到新壁纸开始显示的时间不超过 1 秒。⚠️ 实测约 3s（子进程启动 + 窗口嵌入开销），待优化 |
| NFR-019 | 暂停响应时间 | < 500ms | 从检测到全屏应用到壁纸完全暂停的时间不超过 500ms。暂停/恢复命令通过 PauseSender 快速通道发送，绕过引擎 Mutex 直接到达渲染线程，响应时间：GIF/图片 < 10ms，视频 < 50ms（含 IPC 往返） |
| NFR-020 | 托盘菜单响应时间 | < 200ms | 从点击托盘图标到菜单显示的时间不超过 200ms |

### 6.2 性能测试条件

以上性能指标的测试条件如下：

| 条件 | 说明 |
|------|------|
| 测试硬件 | Intel i5-12400 / AMD Ryzen 5 5600，16GB RAM，SSD，独立显卡或集成显卡 |
| 操作系统 | Windows 11 23H2，无其他重度应用运行 |
| 测试素材 | 视频：H.264 1080p 30fps MP4（10分钟循环）；GIF：500x300 15fps；网页：简单 CSS 动画页面 |
| 测量工具 | 任务管理器（工作集内存）、Process Explorer（CPU 占用）、自定义计时器（启动/切换时间） |
| 测量方法 | 每项指标测量 5 次取平均值；CPU/内存指标在壁纸运行 30 秒后采样，持续观察 60 秒 |
| 暂停态定义 | 壁纸已暂停（非首次启动后未设置壁纸的状态），无全屏应用运行；WebView2 主窗口已隐藏（hide），WebView2 实例保留 |
| 活跃态定义 | 视频壁纸正在播放，主窗口已关闭（隐藏 hide，WebView2 实例保留） |

### 6.3 资源需求

| 需求 ID | 需求名称 | 指标 | 验收标准 |
|---------|----------|------|----------|
| NFR-008 | 二进制体积 | 主进程 < 10MB | Release 编译后的主进程可执行文件不超过 10MB（不含外部 mpv.exe 约 15-25MB 和 WebView2 Runtime 系统组件） |
| NFR-009 | 无运行时依赖 | 无需 .NET/JRE | 不依赖 .NET Runtime、Java Runtime 等大型运行时 |
| NFR-010 | WebView2 依赖 | 系统自带 | WebView2 使用 Windows 10/11 系统自带的 Edge WebView2 Runtime |
| NFR-011 | mpv 依赖 | 外部可执行文件 | mpv 以外部可执行文件（mpv.exe）形式随程序分发，通过命名管道 IPC 通信（非 libmpv 动态链接库） |

### 6.4 可靠性需求

| 需求 ID | 需求名称 | 描述 |
|---------|----------|------|
| NFR-012 | 内存安全 | 利用 Rust 所有权系统，杜绝内存泄漏、悬垂指针、缓冲区溢出等内存安全问题 |
| NFR-013 | 子进程隔离 | mpv.exe（视频壁纸）和 mirrorstar-wp-proc.exe（网页壁纸）以子进程方式运行，崩溃不影响主进程。GIF 和静态图片壁纸在主进程内渲染（GDI 双缓冲），无子进程 |
| NFR-014 | 子进程恢复 | 🔧 未实现（当前子进程非预期崩溃后不自动重启，需用户重新设置壁纸；未来改进：通过 ProcessManager::is_running() 检测 + 自动重启实现）。注：全屏进入/退出触发的暂停/恢复与 Terminated 渲染器重启（resume_all_fast）已实现，但非崩溃场景追踪 |
| NFR-015 | 配置容错 | 配置文件损坏时使用默认值启动，不崩溃 |

### 6.5 可维护性需求

| 需求 ID | 需求名称 | 描述 |
|---------|----------|------|
| NFR-016 | 模块化架构 | 壁纸渲染器通过 `WallpaperRenderer` trait 统一抽象，4 种渲染器（ImageRenderer/GifRenderer/VideoRenderer/WebRenderer）实现统一接口（play/pause/resume/set_volume/set_speed/set_position/terminate 等），便于扩展新壁纸类型 |
| NFR-017 | 日志记录 | 记录关键操作和错误日志（tracing），便于问题排查 |
| NFR-018 | 代码文档 | 公共 API 和关键模块有完整的文档注释（rustdoc） |
