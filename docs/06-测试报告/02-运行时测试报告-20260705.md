## 3. 测试方法

1. **环境准备**：创建 `target/debug/mpv` 目录 junction 指向仓库根 `mpv/`，使 `find_mpv()` 定位到 `mpv.exe`；清理上一轮日志。
2. **启动验证**：后台运行 `npx tauri dev`，观察 Vite 就绪、Rust 编译、应用启动日志，记录冷启动耗时与启动事件。
3. **静态壁纸测试**：用户在 GUI 点击 PNG 卡片设置壁纸，视觉确认桌面背景更换，采样主进程资源占用，验证无 mpv 子进程。
4. **视频壁纸测试 #1（线稿）**：用户在 GUI 点击线稿 MP4 卡片，验证 mpv 启动、IPC 连接、窗口嵌入；测试音量/静音、暂停/恢复；采样主+mpv 资源；记录切换耗时。
5. **视频壁纸测试 #2（彩色）**：用户切换至彩色 MP4，验证旧 mpv 替换、新 mpv 启动；采样资源并与线稿对比。
6. **托盘与退出测试**：用户点击主窗口 X 验证隐藏到托盘；通过托盘菜单退出，验证 mpv 终止、壁纸恢复、进程清理。
7. **资源采样**：使用 PowerShell `Get-Process` 采集 `WorkingSet64`、`TotalProcessorTime`、`Threads`、`Handles`，每态多次采样取稳定值。
8. **回归验证**：通过运行时日志、用户 GUI 反馈、静态代码审查三种手段逐项验证历史 Bug #1~#6。

## 4. 功能测试结果

### 4.1 启动流程 ✅

- Rust 增量编译完成（9m 02s 首次冷编译），Vite 在 http://localhost:1420 就绪。
- 应用进程 21:19:47 启动，日志系统初始化完成，托盘图标出现。
- **观察项 O-1**：21:19:48 首次查找 WorkerW 失败（`未找到 WorkerW 窗口`），后台预初始化失败但未阻塞启动；15 秒后（21:20:02）`workerw_check` 检测到失效并重新初始化成功（progman=131336, workerw=132032）。**自愈机制正常工作**。
- 配置文件监视、TaskbarCreated 监听、Explorer 重启监控消息窗口全部就绪。
- 冷启动耗时约 **4 秒**（Debug + 弱环境，详见 6.5）。

### 4.2 静态壁纸（PNG / Native 模式）⚠️ 部分通过

- 视觉确认：PNG 壁纸作为桌面背景正确显示。
- 主进程资源占用接近空闲态，**无 mpv 子进程**（Native 模式零渲染开销，符合 NFR 11.8）。
- **观察项 O-2（Bug #1 部分回归）**：日志记录 `asset protocol not configured to allow the path: c:\Dev\DevWorkspace\mirrorstar-wallpaper\wallpaper\【哲风壁纸】少年毛泽东-山水.png`。`tauri.conf.json` 的 `assetProtocol.scope.allow = ["$APPDATA/mirrorstar/**/*", "$HOME/**/*"]`，而测试素材位于 `c:\Dev\...`（非 `$HOME`，Windows 上 `$HOME` 通常为 `C:\Users\<user>`）。前端缩略图加载失败，但壁纸仍通过 Native API 设置成功（不依赖 asset protocol）。
  - **判定**：Bug #1 修复对 `$HOME` / `$APPDATA/mirrorstar` scope 内资源有效；对开发期位于工作目录下的素材仍报错。属于 scope 配置策略问题，不影响生产部署（生产环境素材应位于 `$APPDATA/mirrorstar`）。

### 4.3 视频壁纸 #1（线稿 MP4）⚠️ 部分通过

- 21:26:29 mpv 子进程启动（PID 5276），日志 `找到捆绑的 mpv path=...target\debug\mpv\mpv.exe`，符号链接定位正常。

- **音量/静音（Bug #3 回归 ✅）**：用户反馈"声音按钮正常"，静音可正常切换。日志记录 `ToggleMute set_process_volume 失败 未找到进程 5276 的音频会话`（4 次），但实际静音通过 mpv IPC `set_property mute` 完成，音量控制不受影响。

### 5.2 关键观察

- **主进程内存**：视频壁纸态（30.36 / 30.86 MB）反而低于静态壁纸态（36.65 MB），符合架构设计 —— 视频壁纸主进程仅负责 IPC 与窗口管理，渲染全部下沉至 mpv 子进程；静态壁纸态主进程承担配置/缩略图/WorkerW 窗口管理等开销。
- **mpv 子进程**：彩色视频（204 MB）高于线稿（152 MB），主要差异来自视频码率与色彩复杂度。CPU 占用 18~24% 单核，符合 mpv 软解预期（壁纸场景未启用硬解或硬解失败需进一步确认）。
- **空闲态**：22.17 MB，略高于 NFR-001 暂停态目标（< 20 MB），但本次为"启动后未设置壁纸"的空闲态而非"壁纸暂停态"，且为 Debug 构建。Release + 真正暂停态预计达标。

### 6.1 Debug 构建 vs Release 构建差异分析

- **NFR-001（暂停态内存）**：Debug 构建包含 debuginfo 与未优化代码，二进制体积大、内存占用高 20~40%；Release 构建预计主进程暂停态 < 15 MB，达标。
- **NFR-005（冷启动）**：本次 4s 包含 Vite 首次依赖优化（940ms）与 Debug 二进制加载；Release 构建无 Vite（前端已构建为静态资源），二进制加载更快，预计 < 1.5s，达标。
- **NFR-007（壁纸切换）**：与构建类型无关，主要受 mpv 子进程启动 + IPC 连接影响。本次线稿 1.21s 略超源于前端 scope 错误重试，修复 Bug #1 scope 配置后预计全部 < 1s。

### 7.2 本轮新发现 Bug

#### Bug #7：视频壁纸暂停/恢复需点击两次

| 项目 | 内容 |
|------|------|
| 严重程度 | High（影响核心交互） |
| 现象 | 视频壁纸播放时点击暂停按钮，按钮可点击（非灰色），但首次点击不生效，需点击第二次才进入暂停状态；恢复同样需双击。音量/静音按钮正常。 |
| 日志佐证 | 21:26:55 `ERROR mirrorstar_core::wallpaper::video 视频暂停失败 error=IPC 超时: IPC 读取超时` |
| 根因 | 三个设计缺陷叠加：<br>1. **`set_property` 同步等待 ack 超时**：`crates/mirrorstar-core/src/ipc/mpv_protocol.rs:60-78` `send_command` 同步循环等待 request_id 匹配响应（请求-响应模式），`crates/mirrorstar-core/src/ipc/client.rs:120` `read_line_with_timeout` 5 秒超时抛出 `IpcTimeout("IPC 读取超时")`。<br>2. **`pause_wallpaper` 过早 emit 事件**：`src-tauri/src/commands/wallpaper.rs:346` 在 IPC 调用前已 emit `wallpaper-state-changed` 事件，前端按钮状态先于后端实际暂停切换，导致首次点击后 UI 已切到"暂停"但后端仍播放，第二次点击实际触发"恢复"。<br>3. **pause 线程不 emit 事件**：`crates/mirrorstar-core/src/wallpaper/video.rs:311-322` pause 线程在 `ipc_client.pause()` 阻塞等待 ack 超时后，仍设置 `shared_state.state = Paused`，但不 emit 事件，前端无感知。 |
| 涉及文件 | `crates/mirrorstar-core/src/ipc/mpv_protocol.rs`<br>`crates/mirrorstar-core/src/ipc/client.rs`<br>`crates/mirrorstar-core/src/wallpaper/video.rs`<br>`src-tauri/src/commands/wallpaper.rs` |
| 修复建议 | 1. 改 `set_property` 为 fire-and-forget（不等待 ack），或缩短超时至 200ms 并降级为 WARN；<br>2. `pause_wallpaper` 在 IPC 调用成功后再 emit 事件，或在 pause 线程完成后统一 emit；<br>3. pause 线程无论超时与否，状态切换后均 emit 事件。<br>4. 修正 `video.rs:126` `ipc.connect(100, 200)`（20s）与文档 `性能优化-Performance.md` 11.11 节承诺的 `(5, 200)`（1s）不一致 —— 见观察项 O-8。 |
