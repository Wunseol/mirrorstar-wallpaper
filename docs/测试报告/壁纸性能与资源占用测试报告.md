dev 模式下应用二进制位于 `target/debug/mirrorstar-wallpaper.exe`，`find_mpv()` 查找 `{exe_parent}/mpv/mpv.exe` 即 `target/debug/mpv/mpv.exe`。通过创建目录符号链接 `target/debug/mpv` → `mpv/`（项目根目录下的 mpv 捆绑目录），使 dev 模式下 mpv 可被正确定位。

```

```

### 3.2 资源采样方法

通过 PowerShell `Get-Process` 采样主进程和 mpv 子进程的：
- `WorkingSet64`（工作集内存）
- `CPU`（累计 CPU 时间，两次采样差值除以间隔得到百分比）
- `Threads.Count`（线程数）
- `HandleCount`（句柄数）

每种状态采样 5 次，间隔 3 秒，取稳定值。

## 7. Bug 列表

### 本次测试发现的 Bug

#### Bug #1: Asset protocol 拒绝访问壁纸文件和缩略图 [严重程度：中]

- **严重程度**：中等（P2）
- **状态**：✅ 已修复（v3.1）
- **现象**：前端通过 `convertFileSrc()` 加载壁纸源文件和缩略图时，asset protocol 拒绝访问，日志记录 3 次 ERROR。
- **错误日志**：
  ```
  20:02:16 ERROR tauri::protocol::asset: asset protocol not configured to allow the path: 【哲风壁纸】少年毛泽东-山水_faf8a3.jpg
  20:02:21 ERROR tauri::protocol::asset: asset protocol not configured to allow the path: c:\Dev\DevWorkspace\mirrorstar-wallpaper\wallpaper\【哲风壁纸】少年毛泽东-山水.png
  20:07:05 ERROR tauri::protocol::asset: asset protocol not configured to allow the path: c:\Dev\DevWorkspace\mirrorstar-wallpaper\wallpaper\【哲风壁纸】光影-动漫美女-彩色.mp4
  ```
- **根因**：`tauri.conf.json` 中 asset protocol scope 仅允许 `$APPDATA/mirrorstar/**`，但壁纸源文件以用户选择的原始绝对路径存储（任意位置），不在 scope 范围内。
- **涉及文件**：`src-tauri/tauri.conf.json` 第 21-26 行（`assetProtocol.scope`）
> **v3.0 复盘备注（2026-07-03）**：实测 `tauri.conf.json` 中 `assetProtocol.scope` 当前为 `["**"]`（通配符，允许全部路径），与上述根因分析中"仅允许 `$APPDATA/mirrorstar/**`"不一致。推测测试期间 scope 曾被收紧为 `$APPDATA/mirrorstar/**`（导致 Bug #1），其后可能被回退为 `["**"]`。Bug #1 在 scope 为 `["**"]` 时不会复现，但 `["**"]` 未达"最小化"安全目标，需以白名单方式重新收紧（详见 [优化文档 v3.0 勘误](../优化文档/项目优化计划.md)）。
> **v3.1 修复备注（2026-07-04）**：scope 现已收紧为 `["$APPDATA/mirrorstar/**/*", "$HOME/**/*"]`，$HOME 和 $APPDATA 路径的壁纸文件可正常访问。已知限制：非 $HOME 路径无法预览（但缩略图在 $APPDATA 可访问，壁纸设置走原生 Windows API 不依赖 asset protocol）。详见 [优化文档 v3.1](../优化文档/项目优化计划.md)。

- **修复建议**：
  1. 扩大 scope 允许壁纸文件所在目录，或
  2. 添加壁纸文件时将其复制到 `$APPDATA/mirrorstar/wallpapers/` 下并存储新路径

#### Bug #2: 全屏检测误触发 [严重程度：高]

- **严重程度**：高（P1）
- **状态**：✅ 已修复（v2.1）
- **现象**：设置视频壁纸时，全屏检测立即误触发，导致壁纸被反复暂停/恢复。测试期间共触发 4 次（20:02、20:07、20:07、20:11）。
- **错误日志**：
  ```
  20:07:07.322 INFO  视频壁纸开始播放
  20:07:07.326 INFO  检测到全屏应用，暂停壁纸    ← 仅 4ms 后误触发
  20:07:09.097 INFO  退出全屏，恢复壁纸
  20:07:14.739 INFO  检测到全屏应用，暂停壁纸    ← 再次误触发
  20:07:21.253 INFO  退出全屏，恢复壁纸
  ```
- **根因**：全屏检测通过 SetWinEventHook 监听前台窗口变化。壁纸窗口嵌入 WorkerW 或主窗口焦点变化时，检测逻辑将自身窗口误判为全屏应用。
- **影响**：
  - 壁纸被反复暂停/恢复，影响播放体验
  - **直接导致 Bug #4**（暂停按钮灰色）：壁纸处于 Paused 状态时，前端 `state.state !== "Playing"` 导致暂停按钮被禁用
- **涉及文件**：`src-tauri/src/platform/fullscreen.rs`（全屏检测逻辑）

> **v2.1 修复备注**：已在 v2.1 重构中修复——fullscreen.rs 全屏检测逻辑已排除自身窗口和 WorkerW 子窗口，设置壁纸时不再误触发。

#### Bug #3: 静音切换无法取消 [严重程度：中]

- **严重程度**：中等（P2）
- **状态**：✅ 已修复（v3.2）
- **现象**：点击静音按钮后图标变为 🔇，再次点击无法恢复为 🔊。
- **根因**：前端使用 `appState.selectedDisplayId || ""` 传递 display_id，若用户未选择显示器则传递空字符串 `""`。后端 `toggle_mute_fast` 以此空字符串查找 `pause_senders`，但壁纸注册在实际 display_id（如 `\\.\DISPLAY1`）下，查找失败返回 `Ok(false)`，前端将图标设为 🔊 但实际未切换。
- **涉及文件**：
  - `src/scripts/main.ts` 第 101-112 行（前端 mute 按钮 handler）
  - `crates/mirrorstar-core/src/wallpaper/manager.rs` 第 533-551 行（`toggle_mute_fast`）

> **v3.1 复盘备注（2026-07-04）**：N-005 已修复 `toggle_mute_fast` 竞态条件（改为 `toggle_mute_atomic` 在写锁内原子操作），但前端 `appState.selectedDisplayId || ""` 传递空 displayId 的问题仍存在，故 Bug #3 整体仍未修复，需在前端传递实际 displayId。

> **v3.2 修复备注（2026-07-04）**：FE-001 已修复，采用前端 + 后端 + core 三层协同修复方案：
> 1. **前端 `src/scripts/ipc.ts`**：5 个函数（setVolume/toggleMute/setSpeed/getWallpaperState/setScalingMode）统一 `displayId || null` 转换，参数类型改为 `string | null | undefined`，与 `pauseWallpaper`/`resumeWallpaper` 对齐。新增 7 个 ipc 序列化测试。
> 2. **后端 `src-tauri/src/commands/wallpaper.rs`**：同 5 个命令 `display_id` 改为 `Option<String>`，新增 `resolve_display_id` 辅助函数在 display_id 为 None 时回退查找活跃壁纸。新增 2 个后端集成测试（`test_first_active_display_id_*`）。
> 3. **core `crates/mirrorstar-core/src/wallpaper/manager.rs`**：新增 `first_active_display_id()` 公共方法，返回当前活跃壁纸的第一个 display_id，供后端 `resolve_display_id` 调用。
> 4. **前端 `src/scripts/main.ts`**：消除 `|| ""` 与 `|| undefined` 混用（FE-014 一并修复），统一为直接透传 `appState.selectedDisplayId`（由 ipc.ts 层统一处理 null 转换）。
>
> 影响范围：5 个核心 IPC 函数（toggleMute/setVolume/setSpeed/getWallpaperState/setScalingMode）。`getWallpaperState` 返回 null 还会导致 `updatePlaybackButtons` 误判为"无活跃壁纸"（Bug #4 的部分表现），随 FE-001 一并解决。详见 [优化文档 v3.2 附录 A.11.3](../优化文档/项目优化计划.md#a113-bug-3-修复fe-001)。

#### Bug #4: 暂停按钮始终灰色 [严重程度：高]

- **严重程度**：高（P1）
- **状态**：✅ 已修复（v2.1）
- **现象**：视频壁纸播放期间，暂停按钮始终灰色不可点击。
- **根因**：**Bug #2 的直接后果**。全屏检测误触发将壁纸暂停，壁纸状态变为 `Paused`。前端通过 `wallpaper-state-changed` 事件更新按钮状态时，`state.state === "Paused"` 而非 `"Playing"`，因此 `pauseBtn.disabled = !isPlaying = true`（禁用）。
- **额外问题**：前端按钮状态仅在 `wallpaper-state-changed` 事件中更新，且 `get_wallpaper_state_fast` 对 Native 壁纸返回 `None`（前端收到 `null`），导致 `if (state)` 守卫跳过更新，按钮可能永久灰色。
- **涉及文件**：
  - `src/scripts/main.ts` 第 254-265 行（按钮状态更新逻辑）
  - `src/styles/main.css` 第 321-324 行（`.btn-primary:disabled` 样式）

> **v2.1 修复备注**：Bug #2 的直接后果，随 Bug #2 在 v2.1 修复后解决；前端按钮状态初始化也已改进（壁纸状态查询后主动更新按钮）。

#### Bug #5: 关闭主窗口导致应用退出 [严重程度：高]

- **严重程度**：高（P1）
- **状态**：已修复（prevent_close + hide() 实现，见 src-tauri/src/lib.rs:265-270）
- **现象**：点击主窗口 X 按钮后，窗口被销毁而非隐藏，应用整体退出，托盘图标消失。
- **根因**：`on_window_event` 中 `CloseRequested` 处理器调用 `window.destroy()` 而非 `window.hide()`。`destroy()` 销毁窗口后 Tauri 检测到无可见窗口，应用退出。
- **错误代码**：
  ```rust
  // src-tauri/src/lib.rs 第 229-241 行
  .on_window_event(|window, event| {
      if let tauri::WindowEvent::CloseRequested { api, .. } = event {
          api.prevent_close();
          MAIN_WINDOW_CLOSING.store(true, std::sync::atomic::Ordering::SeqCst);
          let window = window.clone();
          std::thread::spawn(move || {
              std::thread::sleep(std::time::Duration::from_millis(50));
              let _ = window.destroy();  // BUG: 应为 window.hide()
              MAIN_WINDOW_CLOSING.store(false, std::sync::atomic::Ordering::SeqCst);
          });
      }
  })
  ```
- **涉及文件**：`src-tauri/src/lib.rs` 第 238 行
- **修复建议**：将 `window.destroy()` 改为 `window.hide()`，并移除 `MAIN_WINDOW_CLOSING` 相关的延迟销毁逻辑（hide 不需要延迟）。

#### Bug #6: 应用退出时未清理 mpv 子进程 [严重程度：严重]

- **严重程度**：严重（P0）
- **状态**：已修复（perform_shutdown_blocking 实现，见 src-tauri/src/lib.rs:304-308）
- **现象**：应用退出后视频壁纸继续播放，mpv 子进程（PID 4136，94.63MB）孤立运行，需手动杀死。
- **根因**：`perform_shutdown()` 函数（`state.rs:100-145`）实现正确（调用 `engine.shutdown()` 终止 mpv、恢复壁纸、释放资源），但**未在窗口销毁/应用退出路径中调用**。仅在以下两处调用：
  - 托盘 quit 菜单处理器（`lib.rs:160`）
  - `quit_app` 命令（`system.rs:37`）
- **日志佐证**：应用退出后日志无任何 shutdown/cleanup 条目。
- **影响**：
  - mpv 子进程孤立，持续消耗 CPU（22-33%）和内存（79MB）
  - 桌面壁纸无法恢复为原始壁纸
  - 配置文件未刷写（防抖期间未写入的配置丢失）
  - COM 句柄、WinEvent Hook 未释放（资源泄漏）
- **涉及文件**：
  - `src-tauri/src/state.rs` 第 100-145 行（`perform_shutdown` 实现）
  - `src-tauri/src/lib.rs` 第 229-241 行（窗口关闭处理器，未调用 `perform_shutdown`）
- **修复建议**：
  1. 在 `tauri::Builder::run` 的 `RunEvent::ExitRequested` 或 `RunEvent::Exit` 回调中调用 `perform_shutdown`
  2. 或在 Bug #5 修复后，确保仅通过托盘 quit 菜单退出（此时 `perform_shutdown` 已被调用）
